# AddMyID

A consumer-facing reference site that helps US residents add their digital ID or passport to their phone. Live at [addmyid.info](https://addmyid.info).

## What it does

Has a page for all 50 US states. The 21 states and territories with live programs include step-by-step setup instructions for Apple Wallet, Google Wallet, Samsung Wallet, and state-specific apps, plus US passport support for Apple and Google Wallet. The remaining 29 states show a not-yet-available page with information on how to encourage state legislators to launch a program.

## Tech

Built with [Astro](https://astro.build) and Tailwind CSS. Fully static output.

## Project structure

```
src/
  data/
    states/          # One JSON file per state/territory
    platforms.json   # Apple, Google, and Samsung Wallet guide data
    map-paths.json   # Pre-projected SVG path data for the US map (generated by scripts/gen-map.mjs)
  pages/
    index.astro      # Homepage with map, state grid, and wallet section
    state/[state]    # Per-state detail page
    guides/[platform] # Per-wallet guide page
  components/
    Logo.astro       # SVG logo (ID card + checkmark) + wordmark, used in header
    StateSearch.astro
    USAMap.astro     # Interactive SVG map (Albers USA projection, 975×610 viewBox)
    WalletCard.astro
  layouts/
    Layout.astro     # Shared nav, header, footer, meta tags
public/
  robots.txt
  llms.txt           # AI agent discoverability (llmstxt.org convention)
```

## Adding a state

Drop a new JSON file in `src/data/states/` following the schema in `_template.json`. No code changes needed — the state will appear automatically in the grid, search, and map.

State JSON supports these optional fields beyond the base schema:
- `official_url` — shown as a prominent link at the top of the state page
- `notes` — freeform text shown below the state name

## Wallet guide pages

Platform data in `platforms.json` supports:

- `supported_documents` — listed under "What you can add"
- `requirements` — listed under "What you need"
- `step_groups` — array of `{ title, steps }` for multi-section instructions (used when a platform supports both state IDs and passports); falls back to `general_steps` if absent
- `participating_states` — optional array of state names rendered as a list on the guide page (used by all three wallets)

Individual wallet entries within a state JSON support:
- `note` — renders an amber callout above the steps (use for important caveats, e.g. non-standard mDL apps)

## Analytics

Traffic is tracked via [GoatCounter](https://www.goatcounter.com) — a lightweight, privacy-friendly, no-cookie analytics tool. The script is loaded in `Layout.astro` and fires on every page. Dashboard is at [addmyid.goatcounter.com](https://addmyid.goatcounter.com).

## SEO and discoverability

- Open Graph, Twitter Card, and canonical URL tags are rendered by `Layout.astro` on every page
- JSON-LD structured data (WebSite + SearchAction on homepage, WebPage + BreadcrumbList on state/guide pages)
- `sitemap-index.xml` generated at build time via `@astrojs/sitemap`
- `public/llms.txt` follows the [llmstxt.org](https://llmstxt.org) convention for AI agent discoverability

## Local development

```bash
npm install --legacy-peer-deps   # required due to peer dep conflict between @astrojs/tailwind and Astro 6
npm run dev
```

The `--legacy-peer-deps` flag is also set in the GitHub Actions deploy workflow.

## Deploying

Work happens on `main`. To publish, push to the `published` branch:

```bash
git push origin main:published
```

This triggers a GitHub Actions build that deploys to GitHub Pages with the custom domain.
